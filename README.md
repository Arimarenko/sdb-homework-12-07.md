# Домашнее задание к занятию "`Репликация и масштабирование. Часть 2`" - `Римаренко Александра`


### Задание 1
`Опишите основные преимущества использования масштабирования методами`

**1. Активный master-сервер и пассивный slave-сервер**
> Я считаю, что главное преимущество такой схемы него адёжность. Master-сервер обрабатывает запросы и изменяет данные, а slave-сервер хранит их копию. Если основной сервер выйдет из строя, резервный можно переключить в активный режим. Это помогает избежать длительных перебоев в работе системы.

**2. Master-сервер и несколько slave-серверов**

> В этой схеме master-сервер отвечает за запись данных, а несколько slave-серверов могут обрабатывать запросы на чтение. Я считаю, что это удобно, потому что нагрузка распределяется между серверами, и система работает быстрее. Также при отказе одной из реплик остальные могут продолжить работу.

### Задание 2

`Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц:`

1. `пользователи,книги, магазины столбцы произвольно`

**1. Горизонтальный шаринг**

> Горизонтальный шаринг это разделение строк таблиц между несколькими базами данных. Я бы разделила пользователей на три базы по их user_id. Таблицы книг и магазинов разделила бы по store_id, чтобы книги и информация об их магазинах находились на одном сервере. Для распределения запросов я бы использовала маршрутизатор, который определяет, в какую базу нужно обратиться.

**2. Вертикальный шаринг**

> Вертикальный шаринг — это разделение таблиц по столбцам. Я бы разделила данные следующим образом:

> Пользователи: отдельно данные для входа (почта и пароль), отдельно информация о профиле (имя и город).

> Книги: отдельно название, автор и жанр, отдельно цена и количество книг в магазине.

> Магазины: отдельно название и адрес, отдельно телефон и другие данные.

> При необходимости данные из разных частей базы можно объединять по идентификаторам.

**3. Режимы работы серверов**
> Основной сервер (master) будет принимать запросы на запись и изменение данных. Резервный сервер (slave) будет получать копии изменений и сможет обрабатывать запросы на чтение.

> Если основной сервер выйдет из строя, резервный можно переключить в активный режим. Это поможет сохранить работоспособность системы.

**Вывод**

> Я считаю, что горизонтальный шаринг помогает распределять нагрузку и хранить больше данных, а вертикальный разделять информацию по назначению. Оба способа можно использовать вместе для повышения производительности и надёжности базы данных.
